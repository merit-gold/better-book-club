# Better Book Club — Changelog

All notable changes to the Better Book Club project should be recorded here.

This file provides a history of project development, important updates, and approved changes.

## Changelog Format

Each entry should include:

- Date of the change.
- Version or development stage, where applicable.
- What was added, changed, fixed, or removed.
- Why the change was made, when useful.

Use the following categories:

- **Added** — new features, documents, or functionality.
- **Changed** — updates to existing features or decisions.
- **Fixed** — corrections to errors or problems.
- **Removed** — items intentionally removed.
- **Security** — security-related improvements.

## Change History Rules

1. Record meaningful project changes as they happen.
2. Use the actual date of the change.
3. Do not record planned features as completed.
4. Keep entries concise but informative.
5. Do not delete historical entries simply because a decision changes.
6. Record major approved changes to the project direction.
7. Link changes to relevant decisions when useful.

## Versioning

Version numbers may be introduced when the project reaches meaningful development milestones.

For example:

- `0.1.0` — Initial project foundation.
- `0.2.0` — Initial website implementation.
- `0.3.0` — Core functionality.
- `1.0.0` — First approved public release.

These are illustrative examples, not confirmed release dates or commitments.

## Guiding Principle

The changelog must provide an honest history of what has actually happened to Better Book Club.

It should help future collaborators understand how the project has evolved without confusing planned work with completed work.
